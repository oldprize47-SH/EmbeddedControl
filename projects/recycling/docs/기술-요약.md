# 자동 분리수거 시스템 기술 요약

## 1. 읽기 범위

과목 이야기·팀 역할·시연 결과는 [루트 안내](../../../README.md), 소스 탐색은 [컴포넌트 안내](../README.md)에 있습니다. 아래는 UART, 구동기, 센서와 상태 처리의 상세 기술 기록입니다. 이번 통합에서는 앱 동작을 바꾸지 않았고, 보드 2 지원 구현만 토큰이 같은 루트 `lib`로 통합했습니다. 보드 1의 전용 변형과 두 실행 타깃의 분리는 유지합니다.

## 2. 요구사항과 설계 선택

prototype의 사용자 흐름은 다음과 같다.

1. 장치가 대기 상태에서 사용자 바코드를 수신한다.
2. 등록 사용자 fixture와 일치하면 사용자 상태를 활성화한다.
3. 제품 바코드를 수신하고 품목 category를 결정한다.
4. 서보가 투입구를 열고, 품목에 따라 분류 스테퍼가 경로를 선택한다.
5. IR 센서가 투입 완료를 감지하면 도어와 분류 mechanism을 복귀시킨다.
6. Board 1이 사용자 인덱스를 Board 2로 전달한다.
7. Board 2가 해당 사용자 포인트를 갱신하고 3개 수거함의 거리를 측정한다.
8. threshold 이내로 판단된 수거함은 만재 메시지를 Bluetooth/UART로 전달한다.

기능을 두 보드로 나눈 이유는 바코드와 다수 구동기를 처리하는 경로와, 여러 timer input-capture channel을 사용하는 거리 측정 경로를 분리하기 위해서다. 이 구조는 주변장치 충돌을 줄이고 각 보드의 책임을 설명하기 쉽다는 장점이 있다. 반면 MCU 간 protocol이 단순한 1-byte 사용자 인덱스이므로 오류 검출, 재전송, freshness 보장이 없다는 한계가 있다.

## 3. 전체 아키텍처

### 3.1 Board 1: 분류 제어기

Board 1은 사용자 입력과 물리 분류 sequence를 담당한다.

- USART6에서 barcode data를 byte 단위로 수신한다.
- 정해진 길이의 문자열을 완성한 뒤 사용자 fixture 또는 제품 fixture와 비교한다.
- 사용자 인식 전에는 제품 분류를 진행하지 않도록 `user_flag`를 사용한다.
- 제품 category에 따라 두 스테퍼 모터의 step sequence와 방향을 선택한다.
- RC servo PWM으로 투입구를 열고 닫는다.
- 반사형 IR 센서의 ADC 값을 이용해 물체 통과/투입 완료를 판단한다.
- 처리가 끝나면 USART1으로 사용자 인덱스를 Board 2에 전달한다.
- 적색, 황색, 녹색 LED로 대기·사용자 인식·투입 진행 상태를 구분한다.

응용 코드는 interrupt handler와 main loop가 상태 flag를 공유하는 구조다. UART handler는 입력 frame을 완성하고, timer/ADC handler는 구동 sequence와 감지 상태를 갱신한다. 이 방식은 소규모 prototype에서 구현이 단순하지만 공유 변수의 일관성, interrupt latency와 blocking delay가 늘어나면 확장성이 떨어진다.

### 3.2 Board 2: 적재량 감시기

Board 2는 사용자 포인트와 수거함 적재 상태를 담당한다.

- USART1에서 Board 1의 사용자 인덱스를 수신한다.
- 배열 범위를 확인한 뒤 해당 사용자 fixture의 point를 증가시킨다.
- 하나의 trigger pulse를 전송하고 세 Echo 입력의 상승·하강 edge를 timer input capture로 측정한다.
- pulse width를 거리로 환산하여 각 수거함의 threshold와 비교한다.
- 사용자 point와 만재 상태를 USART6 경로로 전송한다.

공개본에는 수신 인덱스 bounds check가 포함되어 있다. 이는 원 prototype의 입력값이 배열 범위를 벗어날 때 잘못된 memory 접근이 발생할 수 있는 문제를 완화한다. 다만 packet framing이나 CRC까지 추가한 것은 아니므로 통신 노이즈에 대한 완전한 방어는 아니다.

## 4. 주변장치와 데이터 흐름

### 4.1 UART

- Board 1 USART6: barcode scanner, 115200 bps
- Board 1/2 USART1: MCU 간 사용자 인덱스, 9600 bps
- Board 2 USART6: Bluetooth/상태 메시지, 9600 bps
- USART2: 각 보드의 debug/stdio retarget 경로

수업용 support layer가 USART alternate function과 interrupt를 설정한다. 공개본은 해당 support 변형을 보드별로 분리해 포함하지만 vendor/CMSIS와 startup은 포함하지 않는다.

### 4.2 모터와 상태 표시

Board 1은 두 개의 4상 스테퍼 sequence를 사용한다. 하나는 재활용 품목에 맞는 경로를 선택하고, 다른 하나는 사용자 투입 도어 sequence에 사용된다. RC servo는 PWM pulse width로 투입구를 제어한다. 세 LED는 긴 text display 없이 현재 상태를 즉시 보여 주는 단순한 사용자 interface다.

실물 재검증을 한다면 구동부를 한꺼번에 연결하지 않고 current limit를 둔 전원에서 서보와 각 스테퍼를 개별 검증해야 한다. build 성공은 구동부의 전기·기계 안전을 의미하지 않는다.

### 4.3 센서

IR 센서는 ADC threshold를 이용한 종료 판정에 사용된다. 초음파 센서는 timer capture의 상승/하강 edge 차이로 pulse width를 얻고 거리로 환산한다. 이 구현은 과목 prototype에 필요한 기본 원리는 보여 주지만 다음 개선 여지가 있다.

- 센서별 calibration과 온도에 따른 음속 보정
- 초음파 센서 간 cross-talk 방지를 위한 순차 trigger
- moving average/median과 hysteresis
- timeout, stale measurement, invalid pulse 처리
- threshold를 firmware 상수가 아닌 configuration으로 분리

## 5. 상태 관리와 예외 처리

Board 1은 사용자 인식 여부, 제품 인식 여부, 투입 종료 여부를 flag로 관리한다. 올바른 순서는 사용자 인식 후 제품 인식이며, 처리 종료 시 관련 flag와 barcode buffer를 reset한다. Board 2는 수신한 사용자 인덱스가 배열 길이보다 작은지 확인한 뒤 point를 갱신한다.

공개본에서 유지한 안전·정확성 관련 요소는 다음과 같다.

- 사용자 fixture 개수와 loop bound의 일치
- MCU 간 수신 인덱스 bounds check
- 원 사용자 식별자를 synthetic fixture로 교체
- 보드 1 전용 support와 보드 2 루트 lib의 target별 분리

향후 개선 시에는 enum 기반 명시적 state machine, fixed-size packet header, sequence number, checksum, timeout과 error state를 추가하는 것이 적절하다. interrupt와 main 사이의 공유 상태에는 `volatile`만으로 충분한지 검토하고, 필요한 구간에는 짧은 critical section이나 lock-free event queue를 적용할 수 있다.

## 6. 공개본의 개인정보 및 저작권 처리

원 prototype은 demonstration을 위해 사용자 바코드와 이름을 firmware에 직접 저장했다. 공개본은 사용자용 fixture를 synthetic 숫자와 `User0`~`User9`로 바꾸었다. 제품 category를 설명하기 위한 제품 EAN fixture는 유지했지만 사용자 식별자와 혼동되지 않도록 문서에 목적을 표시했다.

원 제출 보고서와 page render에는 학생 식별자, 학생 실명, 외부 링크와 사람의 신체 일부가 보이는 demo 사진이 포함되어 있어 저장소에서 제외했다. 회로 연결도 1개만 metadata와 시각 내용을 확인한 뒤 포함했다. 영상은 2인 팀의 공동 결과이며 외부 팀원 채널에 게시되어 있으므로 파일을 복제하지 않고 링크만 제공한다.

support 파일은 수업용·공동 수정 코드가 섞여 있고 명시적 재배포 license를 확인하지 못했다. 따라서 새 오픈소스 license를 부여하지 않고, 파일별 provenance를 `ATTRIBUTION.md`에 기록했다. 학생 개인 이름이 있던 주석은 공개본에서 역할 기반 표기로 치환했지만 조직/수업 출처와 기능 코드는 유지했다.

## 7. 검증과 결과 해석

이번 저장소 정리에서 확인한 것은 다음 범위다.

- 최종 보고서 코드와 가장 가까운 응용 소스에서 이미 개인정보를 치환한 공개용 앱을 보존
- 앱에서 실제 호출되는 course support 구현의 symbol closure 식별
- 집합 헤더의 include 관계까지 고려하여 필요한 선언 헤더 포함
- Board 1 전용 HAL과 Board 2의 루트 lib 정본을 서로 다른 target으로 격리
- 원 사용자 barcode, 학생 식별자/실명, 금지 파일이 없는지 정적 검사
- Markdown/C/H UTF-8과 회로 이미지 파일 무결성 확인

반면 다음 항목은 확인하지 않았다.

- 두 보드의 완전한 실행 파일 link 성공 (로컬 통합의 개별 object 컴파일 결과는 BUILDING.md 참조)
- 원 제출 당시와 동일한 compiler/IDE 재현
- MCU flash와 두 보드 통신
- 초음파 거리 오차, barcode 인식률, 모터 위치 오차
- 반복 cycle 신뢰성, 전원 noise와 brown-out 대응

따라서 이 문서의 결과는 설계와 소스 감사의 증거이며, 새로운 hardware 성능 인증이 아니다.

## 8. 회고와 개선 방향

이 프로젝트의 핵심 가치는 여러 주변장치를 개별 실습 수준에서 끝내지 않고, 두 MCU와 실제 구동 mechanism을 하나의 사용자 흐름으로 통합한 점이다. 특히 barcode 입력, 분류 sequence, 거리 측정과 포인트/상태 메시지가 연쇄적으로 동작하도록 책임을 나눈 경험을 보여 준다.

다시 설계한다면 다음 순서로 개선할 수 있다.

1. 보드 간 packet에 version, message type, length, sequence와 CRC 추가
2. blocking delay를 timer/event 기반 상태 전이로 교체
3. 사용자/제품 mapping을 외부 configuration 또는 host database로 분리
4. 센서 validity, timeout, calibration과 filtering 추가
5. host-side parser/state-machine unit test와 fake sensor test 구축
6. STM32Cube/CMSIS version과 reproducible build container/toolchain 고정
7. logic analyzer trace, 거리 fixture, actuator cycle test를 자동 evidence로 남김

이 공개본은 위 개선을 구현했다고 주장하지 않는다. 대신 무엇이 실제 최종 응용 코드이고, 무엇이 수업용 support이며, 어떤 부분이 재현되지 않았는지를 명확히 드러내는 포트폴리오 자료를 목표로 한다.
